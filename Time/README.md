## 历史：学习辅助时钟与候选调度

2026-10-21 本地实现，随后按用户授权完成十台部署与二十组短测。程序默认仍为原有 `legacy` 时钟和调度，云端服务显式启用 `learned + bounded`。节点不修改操作系统时间，也不改变报文、区块格式、候选排名或分叉有效性。实测记录见 [十台部署与短测](../reports/2026-10-21-clock-cloud/REPORT.md)，当前没有稳定的模型性能收益证据。

## 控制链路

1. 同一连接内用令牌关联四时间戳；按配置的监听地址 `IPv4:port` 聚合，一成员只贡献一份最新观测。处理时间、RTT、偏差和本地耗时不合法时拒收。默认至少三个新鲜远端来源，超过四个探测周期的样本失效。
2. 中位数给出目标校正量，MAD 和 RTT 描述观测分歧。基线时间预算为 `max(250us, |剩余偏差| + 3×MAD + RTT95/2)`，准备预算为最近 30 秒已观测工作耗时的 P95，至少 1ms。工作记录最多 256 项。
3. 应用时钟为单调时间轴上的连续分段线性映射。每次变更速率前先积分旧速率，校正速率默认限制为 ±1000ppm；实际总速率还包括实验注入漂移。命令行限制保证总速率为正。最后一个有效来源期限到达时，即使观察线程停滞，也自动停止主动校正。缺少来源时进入保持模式，不强制跳到墙钟。
4. 观察线程默认每 500ms 从负载快照、来源统计和 1/5/30 秒历史提取 32 个特征。两个线性分位数头预测时间误差和准备耗时；各节点加载相同固定权重，滤波、历史和校正状态独立。节点不在线训练。
5. `learned` 模式只允许模型增大稳健基线的时间与准备预算，并据此衰减校正增益；目标中心和最大速率由传统控制器决定。缺文件、错误格式、非有限值、越域输入、越界输出或过期预测均使用稳健基线。`shadow` 只记录预测，控制与 `robust` 相同。
6. 本地遥测用最多 1024 条的队列交给观察线程写盘；队列争用或满时丢弃并计数，最多输出 100,000 行。候选线程不执行磁盘写入。特征历史最多 301 帧，每来源一个状态，成员最多 64 个。

这里的 95% 是离线样本上的经验覆盖率，不是安全边界。网络时延不对称与真实时钟偏移无法仅靠四时间戳区分。监听地址白名单提供受控实验中的稳定去重，**不提供密码学身份认证或拜占庭安全证明**；令牌也不承担认证。当前模式用于可信成员网络，不根据模型异常分数剔除共识成员。

## 候选调度

`bounded` 调度在本轮剩余时间足够时补入当前轮，否则准备下一未来轮；不追补历史轮。预先冻结轮号、时钟映射版本、单调起点、提议截止、收集截止、父哈希、区块高度、数据库状态版本和特征版本。

准备可以在未来轮开始前执行，包含打包、验签和账户/EVM 临时执行；准备结果可丢弃，正式状态不变。每轮在开始准备前即消耗唯一尝试机会，取消或迟到也不再生成第二份。到达起点后重新核对父状态、版本和截止时间，再进入候选池与广播；准备期间父状态改变则丢弃。临时执行缓存仍按完整块体、父状态和版本匹配。

截止时间一经冻结，不随新的模型预测改变。同步追赶与待处理分支中断等待、优先执行。收到的合法迟到区块继续走原有验证与分支处理；本地截止策略不成为共识有效性规则。固定的轮长和候选窗口没有按节点单独调整。

有界模式退出时停止创建新候选，继续处理已经进入候选池的合法块，不通过关闭阶段绕过轮次和来源条件。

## 参数与对照

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--clock-control` | `legacy` | `legacy`、`robust`、`shadow`、`learned` |
| `--clock-sync` | 0 | 是否主动校正；观察和控制模式分开 |
| `--clock-peer` | 空 | 可重复的可信成员监听地址；新模式只采用这些来源 |
| `--clock-min-peers` | 3 | 最少新鲜远端来源；两节点正确性测试显式设为 1 |
| `--clock-max-slew-ppm` | 1000 | 最大校正速率，可设 1..10000 |
| `--clock-model` | 空 | 固定模型 JSON；缺失或错误时回退 |
| `--clock-model-period-ms` | 500 | 特征与推理周期，100..10000 |
| `--clock-model-ttl-ms` | 2000 | 预测有效期，100..60000 |
| `--clock-trace` | 空 | 可选 JSONL；父目录须已存在，每节点独立路径 |
| `--round-scheduler` | `legacy` | `legacy` 或 `bounded`；后者要求连续时钟模式与非零轮长 |
| `--proposal-guard-us` | 500 | 提议预留余量，100..1000000 |
| `--join-current-round` | 1 | 有界调度是否允许补入当前轮；设 0 仅选择未来轮，保留相同准备、观测和保护 |
| `--round-ms` / `--candidate-ms` | 0 / 0 | 沿用既有配置；对照中固定，例如 50 / 12 |

四组实验统一使用 `--round-scheduler bounded`：A=`robust+join-current-round=0`、B=`robust+join-current-round=1`、C=`learned+join-current-round=0`、D=`learned+join-current-round=1`。四组共用候选准备、模型输入采集、版本与截止保护，避免旧路径缺少准备耗时特征影响模型比较。旧的 `legacy` 调度可作为额外历史参照；不混入上述四组。`Test/Cluster.py` 在新控制模式下从清单构造成员白名单，默认来源数仍需与实验节点数匹配。

启动单个本地实验节点的参数示例，使用相同创世配置并分别指定全新数据库。下面未自动启动任何节点：

```powershell
cmake-build-release/boost.exe --data build/manual-clock/node1/db --port 19001 --bind 127.0.0.1 `
  --genesis build/manual-clock/transactions.bin.genesis.json --seed 127.0.0.1:19002 `
  --clock-peer 127.0.0.1:19002 --clock-min-peers 1 --clock-sync 1 `
  --clock-control shadow --clock-model Time/Models/simulation-v1.json `
  --round-scheduler bounded --round-ms 50 --candidate-ms 12
```

默认 ±1000ppm 意味着校正 40ms 偏差需要至少约 40 秒。启动校准时间不计入正式性能窗口；不能用运行中负向跳时来缩短校准。若剩余偏差或不确定性覆盖整个候选窗口，新调度会暂停本地提议，继续同步和接受有效区块。

## 离线训练与真实标签

```powershell
python Test/Clock/Simulate.py --output build/clock-learning/simulation.jsonl
python Test/Clock/Train.py --input build/clock-learning/simulation.jsonl `
  --output Time/Models/simulation-v1.json --report build/clock-learning/training.json
```

训练环境需要 NumPy（`Test/Clock/requirements.txt`），节点推理不依赖 Python 或任何 ML 框架。模型校验特征次序、单位、32 维归一化/域、系数、分位点和标签来源，记录模型文件 SHA-256 与训练数据 SHA-256。源码特征名定义在 `ClockModel.h`，训练端保持同一 `chain-clock-v1-32` 版本。

当前仓库模型由固定种子的受控模拟训练，包含拥塞、抖动、异常报时、非对称时延和混合情形，仅用于接通和验证实现，不能视为十台服务器适用的已验证模型。按整个 run 划分训练、校准和测试；含 `mixed` 场景的整个 run 留到测试，所有节点和相邻窗口一起隔离。校准仅使用校准集，报告同时给出分场景覆盖率。超时/取消的删失样本保留并计数，不把它们伪造为完整耗时，覆盖率只针对已完整观测样本。

真实节点 `--clock-trace` 输出观察与每次候选结局，原始观察没有时间真值，不能直接训练时间误差头。受控实验需独立标定同一主机单调轴上的参考时间，再执行：

```powershell
python Test/Clock/LabelTrace.py --trace build/node1.jsonl --reference build/reference1.jsonl `
  --output build/labeled1.jsonl --run controlled-run-01 --node node1 --scenario congestion
```

参考文件每行含 `steady_us`、`reference_logical_us`、`reference_uncertainty_us`。仅匹配 2ms 内观测，把参考不确定性与对齐间隔计入误差标签。参考必须独立校准；邻居中位数、chrony 输出或仅注入偏差不能自动充当真实标签。合并不同 run 的标注行后按上述命令训练；一个模型包不混用模拟与实机标签来源。

# 实机准备耗时模型（2026-10-22）

`Time/Models/preparation-v1.json` 在原模拟时间误差预测头之外，增加由实机完整准备路径的单调耗时标签训练的浅层分位数树。两个头分别检查自己的域和有效性，准备特征越界不等于拥有真实时钟参考。时间头仍来自模拟；实机时间误差尚未标定。

准备头的 0.75 分位数用于选择**软准备提前量**，不是时钟误差或共识安全边界。在 `learned` 模式且准备头新鲜、域内时，它可以替代历史预算。父状态版本、冻结单调截止、来源数量、接收区块完整验证保持原规则。迟到预测会使本地候选被丢弃，不能放行迟到候选。

`--clock-prepare-quantile 0.75` 让规则控制也使用相同分位数，默认仍为 `0.95`。实验以同一程序、同一模型文件、同一线程和落盘参数比较 P95 规则、P75 规则与模型预测；需要同时报告迟到、取消、实际模型使用及共同链推进。

训练入口 `Test/Clock/TrainPreparation.py`，依赖见 `Test/Clock/preparation-requirements.txt`。旧 A 组完整实验用于训练、B 组校准，C/D 组只作探索性离线验证；新实验不能回填进本次训练。取消发生在完整准备之后，因此其准备耗时是已观测标签，发布结果仍可能删失。原始签名数据、运行日志和密钥不入 Git。
# 2026-10-23 候选策略实验开关

新增 `--candidate-timing 0/1` 与 `--candidate-risk 0/1`，均默认 0，供有界候选调度实验使用。

前者在每次调度决策刷新就绪交易数、待处理任务和近期准备/提交 P95，调用冻结的准备模型；其余历史特征仍来自观察线程并受 TTL 约束。它最多寻找两轮内预测可完成的轮次。预测只影响本地工作时机，单调截止、父状态版本及每轮一次约束继续执行。

后者使用主循环独占的四分桶在线 EWMA 模型（是否有待处理块、就绪量是否超过半个最大块）。只有至少 8 个真实有效准备结果、预测失败率达到 0.65、预计工作至少 5ms、剩余窗口不足且已有本地验证候选时，才让主循环先处理现有候选。连续最多让步两次后恢复普通准备。这里的失败指未成功进入本地候选池，不能当成全网最终失败或节省 CPU 的精确标签。

两者不改变块有效性、排序、验签、账户执行、同步落盘或接收迟到块的处理。实验配置与局限见 `Test/Clock/Benchmark/README.md`。

## A2/B2：有界校准与候选保留学习

`--candidate-adaptive 1` 独立启用 A2：继续使用冻结的 `preparation-v2.json`，在决策时刷新已有队列/工作特征，按父状态版本、逻辑轮次、特征/工作版本和粗粒度队列档位缓存预测，最多 10ms。每次使用缓存仍重新检查时间源及时间预算。两个拥塞上下文分别保留至多 128 个完整准备残差；至少 16 个样本后应用残差 P95 校准，修正限制为原预测的 ±25%，且不超过 ±10ms，最低预算 1ms。它是经验性能控制，不承诺条件覆盖率。决策预算路径总墙钟、推理墙钟及缓存命中可观测；这些不是 CPU 独占时间。第一版复用既有 32 维输入，未加入精确候选账户/字节扫描，未重新训练时间误差头。

`--candidate-value 0/1/2` 分别关闭、影子运行或启用 B2。B2 使用两个有界在线逻辑回归头，先预测父分支在延后观察中是否保留，再预测父分支保留条件下该候选是否位于本地链。特征是决策时准备预算、预计距发布时间、父状态年龄、有界就绪量、待处理区块及同父可提交候选标记。每个进程从零权重开始，固定步长 0.08、权重范围 ±4，两个头都达到 12 个真实样本前不让步；没有使用本次未来数据或伪造跳过标签。

本地提交由主循环推进，单看准备结束时父版本是否变化不足以刻画后续分支损失。因此训练标签取准备完成后首次主循环观测、年龄处于 250–500ms 的本地已发布主链快照。超过 500ms、祖先不在快照或进程退出均删失；不能把这个观察标签解释为最终确认或精确 250ms 保留率。只有父分支保留的样本训练第二个头；评估保存决策时概率，不能拿更新后的预测计算准确率。

B2 先选择目标轮次，再用该轮的剩余时间评估。只有同父候选可进入现有提交路径、两头乘积低于 0.35、预测准备至少 5ms 且占剩余时间至少四分之一时让步，连续最多两次。随后仍由原规则验证和提交。候选排名、共识有效性、落盘和全量账户检查不变。执行缓存命中未被等同于本地保留标签，当前模型也不能精确估计反事实 CPU 节省。

`--candidate-lifecycle 1` 只收集有界生命周期及标签；正式对照各组统一设置，并让未启用 B2 的组采用影子模式。A2/B2 均默认关闭。A2+B2 只是组合实验，并无必然相加的收益保证。

实验索引或生命周期启用时，每次成功发布链头同时发布最多 256 个规范祖先及累计交易数。普通追加复用已知祖先，分叉/批量追加补齐变化部分；失败写入不发布。查询得到的是每个节点的原子本地快照，全网共同前缀由观察端求交，仍需 RPC 采集区间和停机后持久化锚点复核。

## 本地 Q1 / B3 独立方案（2026-10-23）

两条路线均默认关闭，未据本地正确性测试声明 TPS 提升。Q1 与 B3 可以单独或组合启用；现有 A/A2/B2 参数保持原含义。

| 参数 | 默认 | 行为 |
|---|---:|---|
| `--work-scheduler 1` | 0 | 摘要与缺失交易回复使用一个独立处理线程、64 条消息及独立 8 MiB 字节预留；重建出的完整块仍走完整验证路径 |
| `--verification-budget N` | 0 | 冷签名验证的共享并发上限；0 在 work-scheduler 开启时自动取硬件线程数减一（范围 1–64），关闭时不限制 |
| `--pool-snapshot 1` | 0 | 每次复制至多 64 个账户的队首交易，在池锁外检查与选择；块内池查找也分成 64 笔一段 |
| `--candidate-marginal 0/1/2` | 0 | B3 关闭、影子或有界行动；要求 bounded 调度，不允许与 active B2 或旧 risk 控制同时启用 |

Q1 的示例附加参数为 `--work-scheduler 1 --verification-budget 3 --pool-snapshot 1`，其中 3 对应后续四核机器上的待验证配置。本地参数不代表已测得的最优线程数。签名许可只包围实际冷验签，不覆盖缓存等待、池/数据库锁、网络或子任务等待；有普通交易等待时最多连续授予四次区块优先许可。许可采用 RAII 释放，退出时排空已有工作。统计中的 verification_wait_ms 包含取得许可的墙钟开销，不能当成 CPU 时间。

池分批读取期间保留父状态读锁，不把 txUserPool 的迭代器带出池锁。账户排序、预算检查与选择移到池锁外，初始账户集合和单段复制仍持有短池锁。静态池下保持原有公钥轮询、nonce 排序、字节/Gas/余额限制；并发新入池交易可能进入较晚的分段，最终仍须经过正常的父状态、签名、账户与持久化检查。该实现不是跨整个交易池的原子快照。

B3 的 12 维输入包含分开编码的交易验签队列、区块验签队列和元数据队列、就绪积压的对数值、准备预算、父状态年龄、已有同父候选交易数、本地计数优势上界、最多 64 笔均匀抽样的池内重合比例，以及剩余窗口。重合率是提示特征，不替代交易或状态验证。

冷启动时只有一个明确规则可以让步：存在仍在缓冲区的兼容候选，其交易数达到本地产块上限，而且预计准备至少 5ms、选定窗口仍开放。此时再次本地准备不能增加该块的交易数量，但仍可能改变交易内容或哈希排名，因此它只是可选调度策略，并非共识等价证明。连续最多让步两次后强制普通准备；行动前复核候选身份。影子模式只记录建议。

对于未满块替代，B3 从零权重在线学习。仅实际完成且决策时有替代候选的准备产生样本：在 250–500ms 本地祖先观察中保留时，标签是 `max(本地候选交易数 - 决策时替代候选交易数, 0) / 本地产块上限`，否则为 0。超时、范围缺失、退出及队列溢出删失；让步不生成假想标签。它是本地保留的计数优势代理，不是全网净新增交易或反事实 TPS。每进程重置，固定步长 0.05、权重 ±4、误差历史 128 项；至少 16 个样本后，预测优势加经验误差余量低于显式成本评分才可建议让步。

成本评分固定为 `0.1 × min(替代候选交易数/本地上限, 1) × min(准备预算/轮次长度, 1)`；余量为 0.05 加近期决策时绝对预测误差均值。二者是待验证启发式，经验余量没有统计置信保证。规则建议、模型建议、实际让步、标签和删失分别记录，不能把规则收益归功于学习。当前没有离线预训练，也没有改变冻结 preparation-v2 或真实时间误差头。

`FlowCorrectness` 覆盖共享计算上限、公平授予、异常释放、完整块处理阻塞时的元数据推进、跨 64 账户分段的选择一致性。账户与分叉回归比较原生/EVM 选择结果。`ClockCorrectness` 覆盖 B3 特征、规则/学习门槛、有界让步、恢复和标签删失；`ClockNetwork` 覆盖 Q1、B3 shadow/active 及组合的实际账本一致性。额外 EVM 路径可在全新目录执行 `python Test/EvmNetworkTest.py --bin cmake-build-release --work build/new-isolated-evm-run --optimized`。
