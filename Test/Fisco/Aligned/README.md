# FISCO v3.7.3 原生转账对齐测试

使用原节点二进制、原样复制的默认配置和十台各一个验证节点。负载调用 `0x100c` 的 `DagTransferPrecompiled.userTransfer`，保留 SDK 原生调用的 DAG 标志，不部署 Solidity 业务合约。

控制机独立 Java 驱动预签名并写入有界内存映射文件；计时前完成准备。1024 个逻辑账户各 10 亿初始余额，金额 1，账户 i 向 i+1 环形转账，与 Chain 签名数据的业务路由一致。五档 20000/30000/40000/50000/60000，各预热 2 秒、测量 10 秒、最多收尾 5 秒。

全局在途额度默认 50000，等于旧十发送端各 5000 的总额度。迁移初版误将总额度设为 5000，实际输入约 6000 TPS；该批次保留为发送受限诊断，不作为目标负载下的容量结果。新观察器读取实际提交样本事件，未提交的计划样本不发起查询。

`NativeRun.py` 复用本目录保存的旧控制器生命周期与配置复制代码；旧测试入口不参与本轮。运行前用 Ansible 暂停常驻 Chain/FISCO，退出后恢复。每轮独立数据库，节点停机并保存证据后，依次单独重开节点，无 PBFT 法定人数，不提交新交易。枚举实际主链交易、复核缺失回调的原生返回码、重建 1024 个预期余额、核对余额守恒及十节点状态根。审计不延长测量。之后按进程身份和路径边界清理独立数据库。

模型及 Chain 测试在本轮暂停。FISCO 吞吐取同一控制机观测的 2 秒和 12 秒端点；全部二十个节点端点须能匹配审计后的主链哈希及累计交易数。保存 RPC 取得区间与缺测，不用 SDK 提交数代替链上成功数。

2026-10-23 继续复测：此前 50000 在途批次在首档触发单入口拥塞，控制机节点落后；零成功延迟样本又触发汇总脚本的缺失字段异常，该轮完整保留为诊断。新批次使用同一控制机、同样在途额度，SDK peers 列出全部十节点，以匹配 Chain 使用全部节点入口的条件（SDK 选择入口仍不同于 Chain 广播每笔交易）。SDK 客户端逐笔错误堆栈改为驱动中完整错误分类计数，节点日志及节点配置原样保留。无成功样本时延迟记为 null，每轮清空区块观察缓存。

停机审计先逐一获取各节点持久化链头，再在最长账本重建余额，核对每个节点自身高度的区块哈希、累计交易数和状态根属于同一条链。所有链头是否相等单独报告；落后节点不自动判定为分叉，也不被忽略，主 TPS 仍取全部十节点共同进度的最小计数。审计阶段只单独开启一个节点，没有 PBFT 法定人数，不延长测量或收尾窗口。

仍有不可消除的差异：FISCO 预编译示例使用逻辑用户名与 SDK 签名者，Chain 使用带连续序号的公钥账户；Ed25519 与 ECDSA、协议编码、TLS、发送广播方式、默认封块参数、持久化语义和最终性均分别说明。单控制端减少发送资源位置的混淆，但不使两套协议完全等价。
