# 候选策略对照实验

`Run.py` 固定十台物理机、每机一个节点，使用同一份 720,000 笔签名原生转账、1,024 账户、顺序广播、128 笔批次。五个版本分别为 N95（历史 P95）、M75（原有学习 P75）、A（决策时 P95 预测与可行轮次）、B（在线无效准备风险模型）、AB。五个目标速率为 20k/30k/40k/50k/60k；每格一次，预热 2 秒、测量 10 秒、停止发送后最多等待 5 秒。每个速率轮换版本顺序，默认共 25 轮。

所有版本共用当前可执行文件，只切换显式参数，默认功能保持关闭。A 使用此前训练并冻结的 `preparation-v2.json`，本次实验数据不参与训练；B 每轮重置，按本节点真实候选结果在线更新四个负载分桶的失败概率，不对跳过的工作虚构标签。A 的原始 P95 训练器和模型验证仍依赖历史整轮实验划分。刷新特征与训练时的周期采样并不完全同分布，因此域检查及历史分位数回退继续保留。

共同参数：50ms 轮次、12ms 候选窗口、最多 6,000 笔/块、同步落盘、4 个 I/O 线程、8 个验签线程；测量查询工作池统一为 2 个线程，减少单个状态查询阻塞整个测量队列。这个测量配置不同于此前的单查询线程实验，跨轮历史数字不能当严格配对结果。

只在目标第 2、12 秒及排空阶段探测共同前缀；保留每次 RPC 的开始和结束时间。TPS 为两个共同前缀累计交易数之差除以各采集区间中点的间隔，同时报告采集区间给出的上下界。每个端点采集跨度必须不超过 0.5 秒，二分查找必须完成。停止生产后重新打开各自实验数据库，无对等连接、无出块，独立核对十个节点的余额、nonce、费用和两个已捕获前缀。后验核对不延长测量或排空时间。缺失、重组或核对失败的端点不产生有效 TPS。共同链被观察到并不表示不可逆最终确认。

每轮保留参数、二进制与模型哈希、发包批次、端点和延迟查询、候选轨迹、停止记录及清理结果。发送器饱和时分别报告目标速率和实际发送速率。停止并核对进程身份后只删除该轮独立数据库。脚本 `--dry-run` 不连接服务器。不要把某一轮最大值解释为长期容量上限或统计显著收益。

本次实测结果见 [十节点候选策略报告](../../../reports/2026-10-23-candidate-policy/REPORT.md)。`Report.py` 接收原始 25 轮目录与失败端点复测父目录，优先保留原轮有效结果，生成完整矩阵、全部尝试、机制指标及图表。`--groups`、`--dataset` 和 `--run-tag` 用于同参数、新数据库、原始签名数据的失败轮次诊断；不要把它们用于挑选较好的重复结果。
