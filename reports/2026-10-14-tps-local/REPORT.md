# TPS 瓶颈方案：本地修改与验证

日期：2026-10-14。基于 Git 提交 `0d2025181b7c29c279925f2aeddb459eef4f9744`，对应此前审阅的核心代码 `c4a8724`。本次在 `chain-throughput` 工作副本修改，完成 Release 构建和全部十一项本地回归。十台服务器部署与吞吐量实验由后续任务执行。

TPS 全称为 Transactions Per Second，表示每秒交易数。本次目标是减少重复候选工作、重组重放和同步写盘等待，让更多时间用于推进共同链。新增代码沿用 PascalCase 函数命名、现有头文件、工作池和直接调用方式。

## 1. 对应的性能证据

[上一轮十台实测](../2026-10-14-six-ten/REPORT.md)中，5 万输入档的一次短测达到 50,041 TPS，该段没有重组，执行缓存命中率为 100%；4 万和 6 万档出现更多重组、候选排队和数据库写调用等待。[代码审阅](../2026-10-14-tps-review/REPORT.md)据此提出先减少这些等待和重复工作。

历史 30 秒三轮对照的新版中位数为 46,130 TPS，与 10 秒单次短测分别记录。本版本的 TPS、延迟和资源改善幅度需要十台同参数复测确定。

## 2. 六处核心修改

| 修改 | 实现位置 | 工作方式与收益路径 |
|---|---|---|
| 分支统一择优 | `Transaction/Fork.h` | `RankFork` 先准备完整父链、共同祖先和累计排名。`ProcessForks` 按累计交易数、高度、哈希排序，每次调度采用一个有效最优分支，减少先切换较弱分支再切换较强分支的写入与重放 |
| 分类预算与在途合并 | `Network/Server.h` | 摘要、补传使用独立的消息数预算；相同完整块或相同完整批次只登记一份在途验证工作，减少候选队列中的重复任务 |
| 提交前比较待处理分支 | `Network/Client.h` | 已有待处理分支或连续后继时，先比较分支再提交本地候选；连续追加使用现有原子批次，减少立即写入后又重组的路径 |
| 按变化账户刷新池 | `Transaction/Transaction.h` | 重组后只检查涉及账户的池内交易，重新计算连续序号和就绪数量，减少扫描整个交易池和重建无关账户索引 |
| 链头发布与异步读块 | `DB/DB.h`、`Network/Blocks.h` | 成功落盘后发布小链头快照；块读取、补传及编码交给现有查询工作池，释放网络线程用于收发、连接和时钟任务 |
| 分类计时与数据库抽样 | `DB/DB.h`、`Network/Client.h`、`main.cpp` | 区分分支、候选、元数据、读块回复和清池工作；可选抽样预写日志、内存表和写限流计时，为参数选择提供依据 |

### 分支处理

累计排名沿用现有共识规则：累计有效交易数多者优先，同数比较高度，最后比较链头哈希。准备排名时记录 `dbStateVersion`，取得提交锁后再次复核；状态已推进时重新调度。候选排名先用于确定尝试顺序，采用时仍逐块执行账户与合约规则。最优候选执行无效时恢复旧状态，再准备下一候选。

每次成功采用后立即结束本次调度。后续收到的分支在下一次调度继续比较。256 块恢复窗口、512 MiB 分支缓存、回滚与重放的原子批次保留。`grouped_commit_blocks / grouped_commit_batches` 的增量比值给出连续追加的平均合并块数；两项只统计多块连续追加。

### 容量与完整内容绑定

摘要类型 39、补传类型 41 各按一条消息计数，合计最多 64 条，与完整块按交易数预留的 40,000 笔容量独立。两类共同受 16 MiB 待处理正文容量约束，交易入口保留原有 48 MiB 正文容量。

在途完整内容登记最多 64 项、32 MiB。指纹覆盖全部编码字节，并再次比较完整字节；类型 43 批次另绑定格式标记。相同块头、修改签名的内容分别验证，合约输入同样在完整内容中绑定。原始块 2/7/22 合并相同内容，批次 43 按整个批次合并；部分重叠批次继续由既有已验证块检查处理。

`VerifyReservation` 管理计数与字节容量；工作引用保持至处理完成，在退出和异常路径释放。在途登记保存一份有界正文副本，后续复测同时观察处理器时间、候选等待和内存增量。

### 增量清池

成功分支发布账户后，通过 `lastBranchUsers` 传入变化账户。`RefreshTxPool(span)` 先减去该账户原有就绪计数，再按最新余额、序号与合约资金预算删除已确认或无效交易，并从新确认序号重建连续前缀。原生交易索引、合约输入、字节计数与就绪数量同步更新；无关账户沿用原索引。

完整 `RefreshTxPool()` 保留作为全局刷新入口。新增回归对比增量刷新与完整刷新，覆盖原生和合约交易、余额变化及回滚后序号缺口。

### 已落盘快照与读块回复

`ChainHead` 保存高度、哈希、累计交易数、状态版本、销毁费用和账户数。初始化、创世、普通提交及成功分支采用分别发布，分支在整个批次成功写入后发布。统计、链头消息、追赶进度及摘要高度初筛读取小快照；完整状态、账户、历史位置仍按原一致性规则查询。

`SendBlockReply` 最多八项在途回复，复用 `queryThreads`。连续块在同一提交共享锁下读取，再编码为原有报文；完成后回到连接 strand，通过 `SendBounded` 执行发送容量限制。新增本地回归在持有数据库独占锁时确认网络 strand 仍能执行其他任务，读块恢复后回复容量归零。

## 3. 新增观测与实验入口

| 观察方向 | 指标 |
|---|---|
| 分支择优 | `fork_schedules`、`fork_selections`、`fork_invalid_candidates` |
| 连续追加 | `grouped_commit_blocks`、`grouped_commit_batches` |
| 候选重复与元数据 | `duplicate_block_work`、`pending_metadata`、`metadata_tasks`、`block_tasks`、`metadata_queue_wait_ms` |
| 增量清池 | `pool_refresh_users`、`pool_refresh_transactions`、既有 `pool_refresh_ms` |
| 块回复 | `pending_block_replies`、`block_reply_tasks`、`block_reply_wait_ms`、`block_reply_read_ms` |
| 已落盘版本 | `state_version` |
| 数据库 | `db_profiled_writes`、`db_wal_sample_ms`、`db_memtable_sample_ms`、`db_delay_sample_ms`、`db_other_sample_ms`、`db_write_stalls_ms` |

新增 `--db-profile 0/1`，默认 0。开启时每 64 次实际数据库写调用抽样一次，阶段时间是样本累计值，分析时除以对应的样本次数增量。原有 `db_write_ms`、`db_writes`、写入字节与执行时间继续记录。

实验计划新增 `parallel_ingress`，默认 `false`。开启时并行发送同批交易，每节点最多一批在途，下一批等待全部当前任务完成；相同字节和账户序号顺序保留。新旧对照统一设置此参数，发送方式变更单列对照。

结果分列交易副本队列、完整候选预算、元数据队列及“已发送唯一交易数减共同链交易数”的逻辑落后量，并保存实际测量跨度与样本数。原有 `sustainable` 公式保留；增加 `tx_sustainable`，使用业务交易队列增长条件。元数据的预算单位已经调整，历史混合队列数与当前混合队列数分别解释。完整字段见 [实验说明](../../EXPERIMENTS.md)。

## 4. 本地验收

Release 构建使用 CMake、Ninja 和 MinGW GCC；完整结果保存在 `data/ctest.xml`、`data/validation.json`。本地回归测试隔离数据目录，网络用例按测试自身的少量节点配置运行。

十一项 CTest 全部通过：ChainCorrectness、AccountCorrectness、ForkStateCorrectness、ThroughputCorrectness、FlowCorrectness、ChainNetwork、AccountNetwork、ForkNetwork、EvmNetwork、ExperimentNetwork、AdmissionNetwork。

新增验收覆盖：累计交易数优先于高度、无效最优分支回退、一次成功采用只产生一次写调用、过期状态版本拒绝采用、已落盘快照发布、读块等待期间网络调度、连续块回复一致性、相同内容在途合并、改签名独立验证、容量释放、元数据独立预算、原生与合约增量清池、并行入口字节与顺序一致、数据库抽样计时可用。

原有原子写盘失败、合约回退、70 个满块的大分支恢复、分区重连、重启恢复、状态守恒与反馈顺序回归继续通过。正确性用例的吞吐量数值用于回归诊断；本版本正式 TPS 由十台实验记录。

本次测试记录与日志已保存。本轮独立测试数据库的递归删除被执行策略拦截，数据库暂时保留，状态见 `data/cleanup.json`。二进制与源文件校验值见 `data/source-manifest.json`。
