# 选举票排序与双线程验证

## 改动

1. 票通过解析和签名检查后进入排序队列，每次取选举分数最小的一张。同分按公钥、消息哈希排序。
2. 入队、开始数学验证、完成验证时检查已经验证通过的前十名。无法进入前十的票跳过；未验证票不改变排名门槛。
3. 两个常驻线程验证同一张票中的不同证明组，默认四组八份。网络消息和区块验证共用线程；当前票完成后，等待的区块优先于普通票。
4. 验证完成后，在同一个数据库读锁内重新检查当前轮次、历史摘要和排名并保存，然后广播。
5. 保留原有整票验证缓存、32 张票总限额、2 MiB 消息总限额和补传。停止时释放全部排队消息。没有增加单份 Work 验证缓存，没有接入新的 VDF 运算实现。
6. Windows 的 Work 文件使用扩展路径，支持较深的数据目录；Linux 发送程序的历史摘要编码调用补上完整命名空间，解决 GCC 编译冲突。
7. 随机种子确定后，本节点立即准备并完整验证自己的票。到达原有分数广播阈值时立即发送，未写入区块时每秒重发；其他节点发送的票继续按原阈值接收。没有改变抽查数量、证明验证条件或选举截止时间。

## Linux 测量

服务器为 `118.122.75.11`，四 vCPU，Montage Jintide C6348。使用 GCC 13、`-O2 -DNDEBUG` 编译同一个测试程序；两组均允许使用 CPU 0、2，即虚拟机报告的两个不同核心。没有运行节点或交易负载。

两组使用参数标定时保存的同一批 32 份不同 Work，`T=65536`，构成四组八份的完整签名票。每种线程设置验证五次，完整票每次都执行所有数学验证，不使用应用层验证缓存。

| 验证方式 | 中位数 | 最小值 | 最大值 |
| --- | ---: | ---: | ---: |
| 一个线程 | 0.835923 秒 | 0.834345 秒 | 0.837367 秒 |
| 两个线程 | 0.420027 秒 | 0.418658 秒 | 0.424383 秒 |

中位数缩短 **49.75%**，速度约为 **1.99 倍**。这组结果衡量票的验证耗时，TPS 由后续百节点测试测量。

复现命令，在同一目录依次执行：

```bash
taskset -c 0,2 ./work_vdf_benchmark_parallel --iterations 65536 --rounds 32 \
  --verify-repeats 5 --verify-threads 1 --verify-only --corpus-dir corpus-65536
taskset -c 0,2 ./work_vdf_benchmark_parallel --iterations 65536 --rounds 32 \
  --verify-repeats 5 --verify-threads 2 --verify-only --corpus-dir corpus-65536
```

逐次测量见 `measurements.json`，参与基准程序构建的源码摘要见 `source-manifest.json`。生产 Work 迭代次数仍为临时值 65536，VDF 生成方法、编码和共识规则没有改变。

## 正确性验证

Windows 完整节点重新编译通过，以下四项 CTest 全部通过：

- `WorkElectionCorrectness`：32 份真实证明串行/并行结果一致，四组分别篡改证明、签名变化、连续关系变化、历史变化、换轮、并发调用和异常恢复。
- `WorkRulesCorrectness`：共识规则和区块票验证路径。
- `WorkTicketQueueCorrectness`：分数与同分排序、32 项和 2 MiB 边界、取出和清空后的空间回收、已验证前十门槛和跨轮记录。
- `WorkStateCorrectness`：数据库恢复及分支状态。

新增 `WorkNetwork` 使用四个真实节点，运行选举、提交交易、停止和重启。Windows 用时 57.03 秒，独立检查 181 个区块、12 张票、4 次含票选举和 5 次名单切换。初始委员会以外的新节点，其首张票在高度 77 由原委员会成员写入区块，确认票经过节点间传输；三张票包含完整的四组历史证明。四个节点重启后的账本、余额与 nonce 一致，消息队列清空，全部进程正常退出。该测试采用每组一份证明缩短运行时间；完整 32 份证明由 `WorkElectionCorrectness` 和上面的 Linux 测量覆盖。

新增统计为 `work_verify_threads`、`work_priority_pending`、`work_ticket_skipped`。后续压测同时记录确认时间中位数、TPS、重组次数、CPU 和这些队列统计。

## 百节点测试准备

100 个节点共用一次链初始化，随后按 8000、9000、10000、11000 TPS 连续测试，每档预热 2 秒、测量 30 秒、结束等待 5 秒。每档使用签名数据的新区间，nonce 和账户状态连续核对。确认时间使用中位数，每档重组使用测量区间的增量。

控制机提前生成真实历史，再为 100 个固定身份计算各自全部历史 Work。百台启动时恢复原账本、创世配置和自己的 Work，等待一次新的五人选举名单生效后开始压测。快照恰在轮末时约需 32 秒，包含下一轮少量区块时约需 64 秒，另计连接和验证。

四档预算 1,216,000 笔交易，启动前要求每台至少 2.16 GiB 空闲。低吞吐、交易未收齐或状态核对失败时停止后续档位，保留结果并清理本轮数据库副本。原账本快照、Work、身份和创世配置继续保留。

Linux 部署脚本 158 项单元测试全部通过。测试步骤见 [RUN_WORK_100.md](../../ansible/RUN_WORK_100.md)，百节点 TPS 尚未运行。

最终 Linux 部署版本为 `work-priority-003`。完整回归 48/48 通过，用时 676.23 秒；部署包为 60,338,880 字节，SHA256 为 `3fbf76ce48246acf23ce78394b5aed511d1374f349b8a939cb6f00136cc5a30b`。控制机已解包同一版本的节点、发送程序及运行库，四个运行程序的动态链接检查通过。部署包已备份到本机。

`prepare-snapshot work100-ready-003` 已离线生成并检查 100 节点恢复配置，没有连接百台服务器。无参数运行入口只显示用法并退出，显式执行 `test` 才会部署和开始测试。构建源码清单与本机生产代码、测试代码和部署代码一致；归档后更新的报告和使用说明另行保存在 Git 中。

## 历史与 Work 准备

`work_history_prepare.py` 在控制机运行五个真实节点，不发送交易。已生成到高度 5282，包含 33 个完整周期，用时 1071.97 秒；停止节点后保存共同账本和每轮区块摘要。原始账户余额及 nonce 保持不变。

`work_prepare` 根据这些摘要和 100 个公钥生成 3300 份真实 Work，同一身份逐轮顺序计算，不同身份并行。生成工具不读取私钥；已有文件经过数学验证后可继续使用。每份证明 346 字节，全部原始数据为 1,141,800 字节。

实际生成使用本机 8 个线程，用时 536.84 秒。上传后，Linux 使用两个线程逐份数学验证，用时 51.08 秒，复用 3300 份，重新生成 0 份。共同账本压缩后为 2,832,008 字节，全部 Work 压缩后为 1,096,397 字节。账本、Work 和测试身份均保留在控制机，并备份到本机；公开记录只包含公钥、校验值和统计。

`test` 入口要求快照已经准备完成。每台只接收自己的 Work；`ClusterWorker` 向本次测试目录复制账本，清理时保留恢复源。恢复检查包括链标识、快照区块哈希、Work 文件加载、新选举名单生效、账户余额和 nonce。

首轮五节点恢复成功读取了每个身份的 33 份 Work，重新计算为 0，但选举未收齐五张票。时间线显示部分票完成验证时已超过第 140 个时间片；区块也会等待普通票使用的验证线程。为此增加上述本节点提前验证和区块优先调度。首次失败结果保存在 `preparation.json`，修正后的恢复结果单独记录。

补上区块打包时的分数门槛后，Windows 五节点快照恢复用时 265.81 秒通过。每个节点读取 33 份历史 Work，旧证明重算为 0；第 35 轮收齐五张各含 32 份证明的票，第 36 轮采用同一份五人名单。最终五个节点均到达高度 5766、区块哈希一致，每节点 1024 个账户余额和 nonce 检查通过，证明队列清空，进程全部退出。结果保存在 `preparation.json` 的 `windows_restore_after_broadcast_check`，此前结果保留。

同一 Linux 版本在四核控制机同时运行五个节点时，180.33 秒内未完成五人名单恢复。每个节点均加载 33 份历史 Work，旧证明重算为 0；证明队列非空期间服务器 CPU 使用率中位数为 100%。停止时五个节点的区块哈希一致，全部队列清空。这次结果保存在 `linux_restore_after_broadcast_check`。百节点测试按每台一个节点部署。

同一 Linux 部署包在本机 Ubuntu 完成五节点恢复，用时 **64.18 秒**。沿用 180 秒超时和每票 32 份证明，五个节点均直接加载 33 份历史 Work，旧证明重算为 0；第 34 轮选出五人，第 35 轮全部采用同一名单。每节点 1024 个账户余额和 nonce 核对通过，停止时全部节点高度为 5602、区块哈希一致，证明队列清空，五个进程均已退出。原始结果与 500 ms 时间线保存在本机，汇总见 `preparation.json` 的 `linux_restore_local_ubuntu`。
