# 按哈希合并重复交易任务

源码版本：`02f2463fba7f958cec184e756118ae6ea6252c63`。对照版本：`34713f06c7b20f22ad54500490f27696bfb40053`。

## 修改

收到完整交易后计算 `K = H(完整交易正文)`，长度为 256 位，覆盖签名和 EVM 输入。按 K 查询正在处理的交易：相同哈希共用一个任务，只为不同交易预留验签队列数量和字节。比较哈希后不比较完整正文。

若 K 已通过验签且交易仍在当前交易池中，则立即返回已知交易。已验签但不在交易池中的交易继续检查账户余额和 nonce。任务完成后删除登记，失败结果不长期缓存。类型 44 按原批次、原交易位置回复，多个副本不会重复返回首次接收成功。

共识、出块轮换、交易格式和密码学验证规则保持原有实现。记录最多 65536 个不同哈希、48 MiB 正文长度、131072 个回执位置；每个任务记录最多 16 个来源。断开原连接时，已有其他来源的任务继续处理。

## 同机对比

一台 4 核、8 GiB Linux 服务器；每版使用新进程和新数据库。两版复用同一组 10 万笔签名交易，1024 个账户，每秒输入 1 万笔不同交易，持续 10 秒，每笔由 6 条连接分别发送一份，共 60 万份正文。I/O 和交易验证线程各为 2，待验证上限为 32768，交易池上限为 200000。发压期间关闭自动出块，结束后提交相同区块并逐账户核对。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 不同交易处理速度 | 9964.24 笔/秒 | 9972.86 笔/秒 |
| 节点 CPU 时间 | 8.63 秒 | 7.30 秒 |
| 待验证交易数峰值 | 1536 | 256 |
| 实际执行签名验证 | 100000 次 | 100000 次 |
| 工作线程中的验签缓存命中 | 500000 次 | 1588 次 |
| 接收正文 | 600000 份 | 600000 份 |
| 接受不同交易 | 100000 笔 | 100000 笔 |
| 无效或拒绝交易 | 0 | 0 |

修改后 CPU 时间减少 **15.41%**，队列峰值减少 **83.33%**。152862 份副本合并到正在处理的任务，345550 份副本直接命中当前交易池，共 498412 份，占重复副本的 **99.68%**。

两版原有的验签缓存都避免了重复执行签名算法。本次节省来自重复副本不再进入工作队列，减少验签缓存访问和账户、交易池处理。输入固定为每秒 1 万笔，两版均能跟上；100 节点 TPS 和确认时间待集群复测。

不同交易处理速度为 `100000 / 从开始发压到全部正文处理完成的秒数`。CPU 时间只统计节点进程的用户态和内核态 CPU，用于核对状态的后续区块提交不计入。两版最终区块哈希一致，1024 个账户余额、nonce、总供应量核对通过，测试数据库已清理。原始计数见 [metrics.json](metrics.json)。
