# 交易接收、分叉与存储优化

日期：2026-10-14。改动基线：`673ecab`。本轮在本机完成代码修改和正确性回归，十节点性能实验按用户安排随后执行。

## 代码改动

| 路径 | 实现 | 作用 |
|---|---|---|
| 交易索引 | `tx/哈希` 的业务值由 176 字节改为 36 字节，保存区块哈希和四字节交易位置；`DBReadTx` 按位置读取并核对哈希 | 减少重复保存交易内容，单项索引值减少 140 字节 |
| 交易接收 | `poolUsers` 保存已发布账户镜像，成功写盘后按变化账户发布；接收使用镜像共享锁 | 写盘期间继续接收交易；镜像常驻一份原生账户表 |
| 交易池 | 先清理已确认序号；远期交易使用九成容量，连续序号的下一笔使用预留容量 | 让最早缺口有入池机会，保持总容量上限 |
| 状态反馈 | 原生类型 44 请求批次，45 返回逐笔状态；`sender --reliable 1` 重试忙碌项 | 使用原交易哈希和账户序号重试，每批最长等待 30 秒 |
| 分叉查找 | 保存 112 字节块头；共同祖先比较高度对应的哈希，缓存块体通过共享指针复用 | 减少反复读取、解析和复制完整块 |
| 分叉执行 | 共享锁下准备父链和排名，执行前核对状态版本；先处理分支末端；顺序追赶按涉及账户清池 | 缩短独占锁内的准备路径，减少重复分支尝试和交易池重建 |
| 分叉恢复 | `BranchMemory` 按将要改写的账户、代码、存储槽记录旧值，每个键保存一次 | 无效分支和写盘失败按变化键恢复状态，备份量随实际变化增长 |
| 候选队列 | 一个独立候选处理线程；交易和区块验证分别预留计数与正文容量，冷块分片验签使用独立池 | 交易积压时保留区块、同步块的处理容量 |
| 合约执行 | 历史区块哈希按线程和状态版本缓存，分支视图每步重建 | 减少同父状态候选的重复历史查询 |
| 提交清池 | 同一发送账户在一个区块提交后清理一次 | 减少重复账户查找与清理 |

账户、交易执行顺序、分支评分与同步写入参数沿用当前定义。每块的账户、合约状态、索引、回执、费用与链头继续原子保存。镜像在写盘成功后发布；失败分叉恢复缓存时，接收镜像保持先前已发布状态。

## 存储与协议

数据库格式升级至 6，默认目录为 `data/accounts-v6`。启动本版本时使用新目录和创世配置；已有版本 2、3、4、5 的账本保留在原目录。

```text
tx/<交易哈希>       -> 区块哈希（32 字节）+ 块内位置（4 字节，小端）
block/<区块哈希>    -> 完整区块
header/<区块哈希>   -> 112 字节区块头
```

完整交易查询检查索引长度、区块存在性、位置边界和交易哈希。分叉回滚删除退出主链的交易索引，新分支生成自己的索引。完整块与块头保留供后续分支恢复。

状态反馈数组与请求中的交易一一对应：0 已接收、1 已知、2 忙碌、3 无效、4 序号冲突。原生发送器在一个连接内等待本批反馈，再重发其中的忙碌项。固定速率性能对照继续使用原有 1/10 号报文，可靠发送模式单独记录。

交易正文队列预算为 48 MiB，区块正文为 16 MiB；区块验证计数预算为 24,000，交易预算由 `--max-pending` 指定。MiB（Mebibyte）表示二进制兆字节。正文计数按编码报文大小计算。

## 本地验证

Windows Release 构建完成，十一项 CTest 回归全部通过。最终结果记录在 `data/local-validation.json`。

- 原生和合约分叉、写盘失败、嵌套调用、签名篡改、重启及测量索引继续通过既有回归。
- `FlowCorrectness` 验证提交锁持有期间交易仍可接收、池内缺口容量、逐笔状态、36 字节查询、分叉索引切换、重启，以及两个验证队列的容量释放。
- 变化键恢复覆盖合约账户删除后的元数据、代码和 10,000 个存储槽恢复，以及失败分支新建账户和存储槽的清理。
- `AdmissionNetwork` 验证实际网络状态反馈、无效签名反馈、原生发送器重试接口，并独立核对 20,000 笔交易的全部余额和序号。
- 正式计划干运行验证扩大清单后仍只选十个节点；干运行仅生成参数和用例。
