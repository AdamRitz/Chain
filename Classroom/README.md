# NornV2 学术聊天室

用于研究成员之间建立链上聊天室的 Windows 桌面应用。创建链的人负责初始化链和部署公共聊天室；所有成员使用同一套界面和合约接口。每台电脑可保存多条链，任一时刻只运行选中链的一个真实 C++ 节点，支持 IPv4/IPv6。

## 安装

下载 [NornV2 0.4.3 Windows x64 安装包](https://github.com/AdamRitz/Chain/releases/tag/v0.4.3)。通常选择 `NornV2-0.4.3-windows-x64-setup.exe`，双击后选择程序目录并继续安装。关闭正在运行的应用后再安装更新。支持 Windows 10 1903 及以上和 Windows 11 x64。完整桌面包包含界面、本地网关、区块链节点、网络助手及 C++ 运行依赖，保留 RocksDB 11 接口兼容修复，不需要额外安装编译器、Node.js 或 Python。

默认提供一个标准安装包，复用电脑上已有的 WebView2；缺少时通过内置的微软引导程序联网下载安装。项目仍保留完整离线打包脚本，需要时可单独构建，不再把两种安装包并列为默认选择。

安装保留应用标识 `edu.chain.classroom`、既有程序目录 `%LOCALAPPDATA%/Chain Classroom` 和数据目录 `%LOCALAPPDATA%/edu.chain.classroom`，避免重建账户或丢失链数据。显示名称改为“NornV2 学术聊天室”。安装包未做发布者代码签名。

默认双击先显示安装目录，可浏览或输入 D 盘等有写入权限的目录，之后显示进度，成功后自动打开并创建快捷方式。更换程序目录时清理旧程序，账户和链数据仍保留在原来的独立数据目录，不会自动迁移至新盘。高级参数 `/WIZARD` 打开完整向导，`/NOLAUNCH` 安装后不启动，`/P` 显示进度而不启动，`/S` 静默安装，附加 `/R` 才自动启动。无人值守可用最后一个参数 `/D=D:\Apps\NornV2` 指定目录（NSIS 要求不加引号）。普通卸载默认保留账户和链数据。

## 创建聊天室并邀请朋友

1. 点击“创建聊天室”，填写名称。首次使用设置本机账户和昵称；每台电脑启动一个节点。
2. 点击聊天界面或顶栏的“邀请朋友”，软件自动识别 IPv4/IPv6 地址和监听端口。
3. 先从候选地址下拉框中选择对方可访问的地址，再点击“复制地址”，将 `IPv4:端口` 或 `[IPv6]:端口` 发给朋友。复制内容只有节点地址，不带创世配置或长邀请码；即使只有一个候选，也需要明确选择。无需编辑 JSON。
4. 若需要允许朋友主动连入本机，可在邀请弹窗点击“允许朋友连接”，按需确认 Windows 权限。

软件区分跨网候选、局域网和专用网络，并在下拉框标注地址类型和网卡。只有链路本地 IPv6（`fe80::/10`）时，不会把它当成公网入口；VMware 等仅主机网卡不进入自动候选。可用 IPv6 与 IPv4 会列为候选，由用户选择后复制；所选地址在刷新后消失时，需要重新选择。候选不等于外部可达，接收者会进行实际连接检查。

地址采集使用独立的原生网卡接口，不依赖防火墙查询权限。邀请弹窗打开时重新读取，打开期间定期刷新；复制过时的邀请前重新准备。手动公网映射、域名或专用网络入口可在“连接详情与高级设置”中填写。

## 加入聊天室

1. 点击始终可见的“加入聊天室”，空输入框默认填入上次成功连接的地址，并提供复制按钮；也可粘贴其他节点地址。IPv6 使用方括号，例如 `[IPv6地址]:端口`；端口不能省略。也兼容已有域名入口。
2. 软件在后台先连接该地址，通过同一节点端口自动读取创世配置、链指纹和聊天室合约信息并核对。点击“连接并加入”后自动初始化本机节点并同步区块和聊天记录。无需手工传递创世文件；失败不会替换当前聊天室。
3. 界面依次显示连接、同步、就绪状态；本机节点启动不等于已经连上对方。同步记录保留在本机。
4. 同一聊天室的新地址会合并入口，通过本地种子文件通知节点，不重启节点或重建账本。切换其他聊天室时保留原记录；节点启动失败时尝试恢复原来的运行状态。
5. 加入者使用自己的密钥，公开链配置不含私钥。新建 v3 聊天室会自动申请启动金并签名领取合约补贴，无需人工分币；赞助入口暂不可用时等待其恢复。已有 v1/v2 链沿用原有资助规则，余额不足时由有余额成员普通转账。

已经进入聊天室后仍可从顶栏创建链、加入链或选择已保存的链。创建窗口填写链名；加入时读取对方提供的链名和创世指纹。名称可以重复，完整创世指纹是链的唯一标识，可在界面复制；名称保存在链配置和公开邀请元数据中，区块头、共识与交易格式保持兼容。

切换链先正常停止当前节点，再打开目标链原来的数据库并同步；切走的链在本机处于停止状态。各链的账本、聊天索引、余额、待确认交易及连接记录分别保存，重复加入同一聊天室会复用已有记录。关闭 A 链后加入云端 B 链，之后可以从链列表切回 A。未运行的链只占用存储空间，节点的验签、组块和落盘路径保持原样。切换后的同步耗时取决于离线期间积累的区块。

新建 v3 链的创世供给为 9,000,000,000,000,000 个最小单位，初始分配给创建账户；部署聊天室时向合约转入 8,000,000,000,000,000 作为储备。每个身份可领取一次 1,000,000,000,000。零余额新成员先通过绑定链、合约及赞助者的签名证明申请 2,000,000 启动金，赞助网关在线且账户已解锁时自动处理，再由成员自己的签名调用合约领取。手续费继续按普通交易规则收取。

升级不会修改既有 v1/v2 创世配置、合约或钱包，也不会给旧链补发储备；原记录和规则保持有效，0.4.1 发布继续保留。

按地址自动获取链配置由 0.4.0 引入；加入 v3 聊天室需要 0.4.2 或更新客户端。旧节点仍可使用完整邀请码或 JSON；兼容入口收在“旧版邀请码兼容”中。公开配置通过现有节点只读查询提供，不新增公网管理端口、不提供修改钱包或执行系统命令的接口。读取配置有大小和超时限制；不会跟随对方配置中的其他地址。

Windows 安装包只关联专用 `.norninvite` 文件，双击会打开加入预览；已有窗口接收邀请，不自动切换链或执行交易。不改变普通 `.json` 文件关联。邀请码为自包含内容，不依赖短码查询服务；校验值用于检查复制损坏，不证明发送者身份。

仅有内网入口时，双方需要在可互通的局域网或专用网络。跨互联网直连需要可用全局 IPv6、公网映射或同链的可达公网节点。当前版本不会自动配置路由器或部署中继。

创建链时，创世配置另加入一个零余额随机公钥区分独立链。其他新账户初始为零余额，加入 v3 聊天室后按上述流程自动领取入群代币。部署与消息费用按现有节点规则扣除；合约补贴和普通转账不增加总供应量。当前原生转账协议仍不绑定链标识，复用同一账户参与独立链时存在此前审查记录的跨链重放问题，本次更新未修改该协议。

## 平等成员的聊天室

- 新聊天室合约没有 owner、成员白名单、教师审批或关闭其他成员发言的接口。所有有足够费用余额的成员均可发送消息和创建讨论分组。
- 所有已连接成员都可以生成邀请；创建者离线后，已互连的其他成员仍可同步和交流。首次加入至少需要一个仍可达、持有该链记录的成员节点。
- 每条消息对应普通 Solidity 合约交易和事件，公开记录在当前链上。界面区分等待入块、执行失败和本机已上链；本机已上链不是不可逆最终确认。
- 已执行失败的交易不能通过重发同一签名字节重新执行。聊天页的“重新发送”会创建新交易；传输中未入块的交易才使用“重试原交易”。
- “链上记录”和“链状态”供查阅，不再提供教学引导、课堂管理或演示钱包切换。新建账户只生成一个身份；既有多个密钥以普通账户名称保留。

## 连接配置

默认 `Profile=Any + RemoteAddress=Any`，允许所有来源连接当前安装的 `runtime/boost.exe`，适用于专用、公用和域网络，兼容 IPv4/IPv6 和动态节点端口。仅配置本应用节点的 TCP 入站规则，本机管理网关继续只监听回环地址，不更改防火墙开关。

相同规则不会重复请求授权；撤销和卸载只清理当前安装拥有的规则。独立脚本位于安装目录 `runtime/Configure-Network.ps1`，与界面使用相同工具：

```powershell
.\Configure-Network.ps1 -Action status
.\Configure-Network.ps1 -Action configure
.\Configure-Network.ps1 -Action remove
```

防火墙规则不能代替路由器端口映射或校园/机构网络的入站许可。

“节点与连接”显示本机 IPv6 状态，区分只有 `fe80::` 链路本地地址、没有全局地址、没有默认路由及有地址与路由但外部待验证。Windows 使用真实路由表检测默认路由，不要求管理员权限。加入失败可展开“连接详情”，分别查看各入口的无路由、端口拒绝、超时、域名解析失败或链指纹不匹配原因。

两台电脑都启用 IPv6，并不意味着都有跨网络可用的 IPv6。若本机只有 `fe80::`，应先在路由器/上游网络取得全局地址和 IPv6 路由；同一可互通局域网也可以选择候选列表中的 IPv4 入口。程序支持双栈节点互联，不提供 IPv4-only 与 IPv6-only 网络之间的转换或自动中继。

## 已有数据兼容

恢复既有链时，使用原主节点端口、node1 账本、钱包和合约，其他节点目录保留。旧版加密文件中的三个密钥不删除，但没有特殊管理角色名称或客户端管理接口。

支持 v1、v2 和 v3 合约与邀请，默认新建链部署带自动入群补贴的 v3 平等成员合约。已部署的 v1/v2 合约字节码和历史记录不会被客户端改写；其既有链上规则继续生效。邀请被绑定到当前连接，切换连接后不会继续下载另一条链的邀请；无效邀请在停止节点之前完成校验。

v2 邀请需要 0.2.0 或更新客户端，v3 邀请需要 0.4.2 或更新客户端。兼容编译结果分别保存在 `Contracts/ClassroomChat.legacy-v1.compiled.json` 和 `Contracts/ClassroomChat.legacy-v2.compiled.json`；`Contracts/ClassroomChat.compiled.json` 为默认部署的 v3 合约。

## 开发构建

内部 `Classroom/` 目录和既有二进制名称保留，以兼容安装标识和构建脚本；产品界面使用学术聊天室名称。节点共识和账户数据库 schema 7 保持现有无学习模型基线，FISCO 测试方法不受影响。

需要现有 C++20/CMake/MinGW 节点依赖、SQLite3、Node.js 22.12+、Rust 1.90.0 MSVC 工具链和 Windows SDK/MSVC Build Tools。

```powershell
cd D:\Project\Chain\Classroom
npm ci
npm run contract   # 更改 Solidity 后执行，固定 solc 0.8.28 / Shanghai / optimizer 200
npm test
npm run build
cd ..
cmake -S . -B build/classroom -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DCHAIN_BUILD_CLASSROOM=ON -DCHAIN_TEST_DATA_ROOT=D:/Project/Chain/build/chat-check-new
cmake --build build/classroom --parallel 3
ctest --test-dir build/classroom --output-on-failure
cd Classroom
powershell -NoProfile -File scripts/Package-Windows.ps1 `
  -BuildDirectory ../../build/classroom -CompilerBin <MinGW运行库目录> -Installer
```

安装包和校验文件输出至 `Classroom/release/`。`-Installer` 构建标准包；增加 `-OfflineInstaller` 同时构建完整离线包，也可单独指定它。包内包含节点、网关、网络工具、前端以及 v1/v2/v3 三份合约编译结果，并生成运行文件 SHA256 清单。离线配置通过 `src-tauri/tauri.offline.conf.json` 合并，不改写主配置。

验证记录见 [0.2.0 验证数据](../reports/2026-11-03-peer-chat/validation.json) 和 [实际界面](../reports/2026-11-03-peer-chat/figures/peer-chat.png)。

0.3.0 的邀请、原生地址采集、IPv6 回退、同链入口更新和界面验证见 [邀请流程报告](../reports/2026-11-04-invites/REPORT.md)。新增 InviteCorrectness、InviteNetwork；17 项本地 CTest 与 11 项前端测试通过。真实公网 IPv6 入站仍需在有相应网络条件的两台电脑上验证，回环测试不能替代该结果。

0.3.1 的纯邀请码、IPv6 配置诊断和 IPv4/IPv6 成员混合聊天验证见 [本机 IPv6 排查报告](../reports/2026-11-04-ipv6-diagnosis/REPORT.md)。
